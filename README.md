# ScenePilot · 光影选景师

**基于 Deep Agents、Qwen 和高德官方 MCP 的智能人像约拍场景规划后端。**

摄影师输入模特妆造、服饰、摄影风格、场景偏好、自然光线、预算和交通限制，ScenePilot 分析创作意图、调研真实拍摄地点及可查询的驾车路线，并提供拍摄建议与人工实拍核验关键词。

当前版本：**V0.7.0（后端）**。已有 FastAPI 任务接口、实时进度和 SQLite 历史记录，保留 CLI；下一步接入完整操作流程的前端，再扩展多模态。

## 功能

- 本地任务 API：提交、修改、确认需求，启动规划，选择出发位置，查询结果和历史，取消任务。
- 实时进度：SSE 推送固定阶段提示，断线后补发近期变化；查看或重连不重新启动规划。接口错误提供中文说明。
- SQLite 保存需求、确认快照、结果与调用统计；重启后保留历史，运行中的任务标记中断，不自动重新调用外部服务。
- 需求确认：一次模型提取草稿，用户逐项修改并明确确认后才开始地图调研。
- 交通约束：用户选择地图出发位置，路线绑定已确认的出发点和驾车方式，按实际路线估算输出“符合 / 不符合 / 信息不足”。
- Deep Agents 主 Agent：`write_todos` 任务拆解与 `task` 子 Agent 委派。
- Style Agent：分析文字描述的妆造、服饰、摄影风格、背景与光线需求。
- Scene Agent：通过高德官方 MCP 检索真实 POI。
- Route Agent：已知出发地时调用 MCP 查询单程驾车路线。
- Pydantic `PhotographyBrief`：结构化地点、风格、日期、预算、器材、团队和场地条件。
- 实拍核验工具：生成适合在小红书、抖音等平台**人工搜索**的关键词，不抓取网站、不声称已核验实拍图片。
- 流式执行与安全 Trace：日志只记录工具事件、调用次数和模型可用的 Token 统计；需求和结果保存在本地任务数据库，密钥不进入数据库或 Trace。
- 按次运行的地图缓存、并发去重、调用额度和 Agent 预算；失败或额度耗尽时保留已有证据。
- Pydantic 结构化推荐：用户原话、AI 建议、地图实际返回的事实、未知场地信息分开存放。最终地点事实由后端证据记录填充。
- 高德天气 MCP：按候选地点的地图区域匹配拍摄日期的逐日预报；缺失发布时间时标为“时效性未知，仅供参考”。
- 本地 Astral 计算：按北京时间估算日出、日落、晨间和傍晚黄金时段；不代表现场一定有阳光。

## 本地环境

需要 Python 3.12、uv、可用的百炼 Qwen API Key，以及在高德开放平台申请的 Web 服务 Key。

```powershell
uv sync
```

如果根目录没有 `.env`，可从 `.env.example` 复制；已经有 `.env` 的用户**不要覆盖**原有文件：

```dotenv
DASHSCOPE_API_KEY=仅在本地填写
QWEN_MODEL=填写你当前能正常调用的模型
QWEN_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
AMAP_WEB_KEY=仅在本地填写
```

不要上传真实 API Key、含密钥的截图或者完整敏感错误 URL。

先做一次真实模型连通性诊断（可能消耗模型额度）：

```powershell
uv run scene-pilot-check-model
```

运行无需外部密钥的单元测试：

```powershell
uv run python -m unittest discover -s tests -v
```

运行摄影选景：

```powershell
uv run scene-pilot
```

也可以运行 `uv run python -m scene_pilot.main`。

输入例子：

> 我想在杭州拍日系清新写真，模特穿白色连衣裙，淡妆自然披发，希望有树林、草地和柔和逆光。从下沙出发，单程驾车不超过 40 分钟，预算 300 元。请寻找真实候选拍摄地点并给出实拍核验关键词。

输入后先检查需求草稿：输入字段编号修改，输入“确认”才开始选景，输入“取消”返回。
相对日期不会自动确定，可以在确认页填写明确日期。出发地址应具体到实际地点，不能将“下沙”一类宽泛区域当作准确起点。
驾车需求会再展示地图定位结果，需要你选择实际出发位置；不正确时输入“跳过”，仍会给出选景结果，但路线时长保持未知。
40 分钟上限与 55 分钟地图估算会标为“不符合”；费用不完整时不会声称符合预算。

## 本地 HTTP API

```powershell
uv run scene-pilot-api
```

启动后访问 [接口文档](http://127.0.0.1:8000/docs)，使用 [健康检查](http://127.0.0.1:8000/health) 确认服务启动。
启动、查看文档和查询历史不调用模型或地图；提交新需求会尝试一次模型提取，明确确认并启动后才做地图规划。

任务流程：`POST /tasks` → 检查/修改草稿 → `/confirm` → `/start` → 按需 `/origin` → 查询 `/result`。
修改、确认、启动、选择和取消均须携带任务最新的 `revision`，防止接受旧页面上的需求。确认请求必须包含 `accepted: true`。
接入方必须展示草稿并取得真实用户接受，不能替用户自动确认或选择地图位置。

服务默认只监听本机 `127.0.0.1:8000`，数据库为 `data/scene-pilot.sqlite3`。
这是单用户、单进程版本，尚无登录鉴权；不要直接部署到公网。重启不会恢复正在运行的模型/地图调用，需用户主动新建任务。
接口约定、请求示例和验收结果见 [V0.6.0 说明](docs/V0.6.0.md)。

V0.7.0 增加 `GET /tasks/{id}/events`。首次连接返回当前快照，之后推送阶段/状态变化；
断线重连可携带 `Last-Event-ID`，刷新页面后可用 `?after=上次事件ID`。浏览器关闭不取消后台任务，取消仍使用独立接口。
任务详情新增 `progress.phase`、`progress.message` 和 `settled`；HTTP 错误在原 `error_code` 外增加中文 `message`。
进度只包含固定提示与状态，不包含需求正文、地址、坐标、模型自由文本或原始工具响应。
前端接入、事件格式和恢复规则见 [V0.7.0 说明](docs/V0.7.0.md)。

首次用 V0.7.0 打开现有数据库会在事务内从 schema 1 升级到 2，保留需求与历史结果。
若需保留回退到 V0.6.0 的能力，应在服务停止时备份数据库；旧版不能直接读取升级后的 schema。

## 费用与边界

高德地图受个人账户免费额度和使用许可约束；MCP 是通信协议，不等于第三方接口永久免费。Qwen 模型是否计费取决于所用模型及百炼账户的可用额度。

当前只理解**文字描述**，不能实际识别模特照片或参考图片；没有接入小时级或机位级天气、场地商业拍摄许可或真实票价。

地点名称与路线可能来自地图接口，但**不能据此保证某处具备期待的机位、植被、光线或免费开放**。没有现场图像证据时，建议摄影师在社交媒体搜索近期实拍图进行确认。

更多设计见 `docs/ARCHITECTURE.md`。

## V0.3.1 预算与验收

默认每次需求最多 8 次地图尝试，其中搜索最多 2 次、详情最多 3 次；网络重试也占额度。
同次请求的相同搜索/POI 详情缓存 300 秒，重复并发请求只访问一次上游；下一次需求重新建立缓存和额度。
主 Agent 和子 Agent 合计最多 12 次模型调用，每次输出最多 1600 Token；观测到累计 40000 Token 后停止发起后续调用。
模型服务的自动重试已关闭，防止统计之外的重复付费请求。
异步 CLI 整体截止时间为 180 秒，图步骤上限 40。限制可通过 `ExecutionLimits` 传给 `StreamObserver`。

Token 阈值依赖服务端 usage，属于响应后的停止阈值，不是预付费硬上限；已在途的调用可能超过阈值。
`usage_missing` 非零表示存在缺失统计，不能将它解释为零费用。普通三地点任务的真实节省比例尚未测量。

推荐使用 `await StreamObserver(limits=ExecutionLimits(...)).arun(agent, request)`，其返回值包含
`recommendation`（可 JSON 序列化的结构化结果）、`status` 和 `metrics`。每次运行创建新 Observer。
直接调用原始 graph 时必须用 `execution_scope(request)` 建立运行上下文，并自行执行最终结果校验；不要把原始模型自由文本直接提供给用户。
同步 `run()` 仅在事件之间检查耗时，不能抢占阻塞模型；含 MCP 的生产调用使用异步 `arun()`。

最终方案只接受本次工具返回的 `evidence_id`。未提交有效方案时仅展示已取得的地图候选，标记为未完整完成；不展示模型自行编造的地点。
V0.3.1 只认证地图基本字段和驾车里程/耗时；即使返回 `biz_ext.cost`、评分或营业字段，也不将它们自动解释为门票、可入园时间或商业拍摄许可。
未知响应格式会返回 `invalid_tool_response`，不会把自由文本解析成地图事实。

本地验收和指标解释见 [V0.3.1 验收说明](docs/V0.3.1.md)。

## V0.4.0 天气与光照

在需求中提供明确的 `YYYY-MM-DD` 日期，例如：

> 我想在杭州于 2026-10-17 拍日系清新人像，请找公园候选地点，并查询当天的区域天气和日出、日落、黄金时段。

请将示例日期替换成实际拍摄日期。周六、明天等相对日期暂不自动换算；没有明确日期时保持未知。
Supervisor 保存本次需求后，调用 `inspect_shooting_conditions`，一次处理最多三处已有 POI；模型不能自行提交天气数值、坐标或太阳时间。
天气工具是可选能力，未发现工具也可继续选景与本地太阳时段计算。

天气最多尝试 2 次（含重试），仍计入原有 8 次高德总额度，同城相同查询复用缓存。
`available` 表示地区/日期匹配且发布时间在 24 小时内；`reference` 表示缺失发布时间或仅有搜索城市依据；`unknown` 表示缺失、过期、日期不覆盖或查询失败。
高德 MCP 可能省略地点的城市/行政区字段，此时仅按搜索时明确传入的城市提供参考，输出会标注“POI 行政归属未核实”，不把搜索条件当成地点事实。
这些状态均不保证拍摄时刻的天气。实况天气不会替代未来日期预报。

太阳时段按国内选景默认 `Asia/Shanghai`、海拔 0 米，使用高德坐标近似计算；未考虑地形、建筑、树木和云层。
黄金时段采用太阳高度 -4° 至 +6°，不承诺现场光效。V0.5.0 起，CLI 和正式任务 API 均要求用户确认需求；旧版未确认调用仍不能给出符合硬约束的结论。
详细实现、验证结果与已知限制见 [V0.4.0 验收说明](docs/V0.4.0.md)。

## V0.5.0 需求确认与交通校验

CLI 的需求提取最多一次模型调用，计入原有每次请求 12 次模型/40000 Token 停止阈值；本地修改、确认不调用模型。
提取失败可手动填写，不自动重试。地图出发定位计入原有 8 次地图总预算，不增加搜索额度或图步骤上限。
提取最多等待 90 秒；确认后的定位与规划沿用 180 秒执行截止时间，用户选择出发位置的等待时间不计入执行耗时。

`confirm_brief` 是宿主确认入口，不是模型工具。程序接入方必须先展示需求并取得真实用户接受，再将返回的快照传给
`StreamObserver.arun(..., confirmed_brief=..., geocode_tool=..., select_origin=...)`。
`select_origin` 是宿主提供的交互回调：展示本次地图返回的位置，返回用户选择的证据 ID 或 `None`；不得让模型自动代选。
省略确认参数的旧调用仍可调研，但交通约束始终为“信息不足”。不提供位置选择回调则不做出发定位，不生成符合交通限制的结论。

本版只校验已确认的驾车单程时长，`completed` 代表完成方案提交，不代表所有候选符合全部需求。
价格、许可、实际路况和现场效果仍需另行核实。细节与离线验证见 [V0.5.0 验收说明](docs/V0.5.0.md)。
