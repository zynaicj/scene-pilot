# V0.7.0 实时进度与安全重连

## 本轮范围

基于 V0.6.0（`8d51e3e`），增加实时任务阶段、断线恢复显示和中文错误提示。
保留 REST/CLI、需求确认、出发位置选择、原有调用预算及地图证据校验。没有新外部服务或依赖包，没有增加真实付费调用。
下一阶段实现前端完整操作流程；本阶段由自动测试验收，不要求用户手动操作接口。

## 接口变化

新增 `GET /tasks/{task_id}/events`，成功返回 `text/event-stream`。这是只读订阅，连接、刷新和重连均不创建/启动任务。
原任务详情、列表、结果与错误接口保持路径和原字段，只增加以下字段：

| 响应 | 新字段 | 含义 |
| --- | --- | --- |
| 任务详情/列表 | `progress.phase`、`progress.message` | 固定阶段编号与可展示中文提示 |
| 任务详情/列表/结果 | `settled` | 后台工作者已清理完毕，结果不会再因本次收尾而更新 |
| 任务详情/列表/结果、规划结果 | `error_message` | 与原 `error_code` 对应的固定说明；无错误时为 null |
| HTTP 错误 | `message` | 可直接展示的中文提示，保留原 `error_code` |

`settled=true` 也可能处于待确认或待启动状态，不能单独用它判断任务已完成；必须结合终态判断。
`completed` 仍只表示提交完成，不代表全部业务约束符合。

## 事件契约

首次连接发送 `snapshot`；续传发送遗漏的 `update`。下面是示意格式，实际 ID 和版本应从响应获取：

```text
retry: 2000

id: <task_id>:<sequence>
event: update
data: {"task_id":"<task_id>","sequence":8,"revision":5,"status":"running","progress":{"phase":"searching","message":"正在查找候选拍摄地点"},"updated_at":"2026-10-24T01:00:00Z","error_code":null,"error_message":null,"result_available":false,"settled":false}

```

`sequence` 是本任务事件序号，独立于用户提交修改时的 `revision`。阶段变化不会令用户的确认或取消请求过期。
每条数据是当时的完整公开状态快照；消息不包含需求正文、草稿、地址、坐标、结果正文、模型内部文字、工具响应或密钥。
页面应通过原详情接口获取需求与定位选项，通过原结果接口获取最终方案。

| 事件名 | 客户端行为 |
| --- | --- |
| `snapshot` | 用当前状态初始化显示，保存事件 ID |
| `update` | 更新状态并保存事件 ID，按 sequence 去重 |
| `reset` | 旧事件已清理或游标比服务端更新；以该快照重新初始化，再读取详情/结果 |
| `end` | 任务已终止且收尾完成，关闭 EventSource，然后读取结果 |
| `stream_closed` | 服务正在关闭；显示暂时断线，允许稍后重新连接 |
| `stream_error` | 进度存储暂时不可读；显示固定错误信息，可重连或改为查询详情 |

每 15 秒无更新时发送注释心跳 `: heartbeat`；心跳不产生业务事件，不修改任务或调用外部服务。
事件流声明 2 秒重连间隔。终态且已经收到最后事件的连接返回 HTTP 204，停止重复重连。

## 断线与刷新

- 浏览器同一个 EventSource 自动重连时，服务接受 `Last-Event-ID: <task_id>:<sequence>`。
- 刷新页面创建新 EventSource 时，可将保存的 ID 放入 `?after=<task_id>:<sequence>`。同时提供两者时，非空请求头优先。
- 没有游标时直接返回最新快照，不从任务创建开始重放全部历史。
- 每个任务仅保留最近 256 条事件；游标过旧或超前时发送 reset，不能声称已补回全部历史。
- 游标格式错误、属于另一个任务或过长时返回 422；不存在的任务返回 404。此时尚未开始流式响应。
- 断开页面不取消后台任务；主动取消仍调用 `/cancel`，修改/确认仍使用最新 revision。
- 取消先写终态，再取消工作者。部分结果可能随后保存，客户端应等 `end`，或等“终态且 settled=true”，再判断最终结果已稳定。
- 服务重启后，待确认/待启动任务与历史仍可查询；在途任务变为 interrupted。重连恢复的是显示，不是重启模型执行。

前端接入示例（在同源页面使用；不自动确认或启动任何任务）：

```javascript
async function watchTask(taskId, renderStatus, renderResult) {
  const detailResponse = await fetch(`/tasks/${taskId}`);
  if (!detailResponse.ok) throw new Error("读取任务失败");
  const detail = await detailResponse.json();
  renderStatus(detail);
  const terminal = new Set([
    "completed", "incomplete", "budget_exhausted", "failed", "cancelled", "interrupted"
  ]);
  async function loadResult() {
    const response = await fetch(`/tasks/${taskId}/result`);
    if (response.ok) renderResult(await response.json());
  }
  if (terminal.has(detail.status) && detail.settled) {
    await loadResult();
    return () => {};
  }
  const key = `scene-pilot-progress:${taskId}`;
  const previous = sessionStorage.getItem(key);
  const suffix = previous ? `?after=${encodeURIComponent(previous)}` : "";
  const source = new EventSource(`/tasks/${taskId}/events${suffix}`);
  for (const type of ["snapshot", "update", "reset"]) {
    source.addEventListener(type, event => {
      sessionStorage.setItem(key, event.lastEventId);
      renderStatus(JSON.parse(event.data));
    });
  }
  source.addEventListener("end", async () => {
    source.close();
    await loadResult();
  });
  source.onerror = () => {
    // 显示连接状态；不要在这里调用 /tasks 或 /start。
  };
  return () => source.close();
}
```

示例用于说明协议；正式前端还需处理请求错误、游标无效后的清理，以及切换任务时注销旧订阅。
浏览器 EventSource 的事件格式、Last-Event-ID 和 204 行为见 [HTML SSE 标准](https://html.spec.whatwg.org/multipage/server-sent-events.html)。

## 阶段与错误来源

阶段覆盖：整理需求、待确认、待启动、准备服务、查询出发位置、待选位置、规划、风格分析、地点搜索、交通路线、天气光照、最终校验与各终态。
阶段只根据真实宿主状态或已观测到的工具请求产生，模型自由文本不能决定公开提示。
工具请求表示开始尝试，不等于执行成功；并行工具时显示最近观测到的活动，阶段可能重复或改变顺序，不提供虚构百分比或剩余时间。
进度保存失败不重试模型或中断现有图；最终方案依然经过原证据校验。若数据库整体不可写，任务状态和结果也无法保证保存。

HTTP 错误例如：

```json
{"error_code":"revision_conflict","message":"任务内容或状态已更新，请刷新后重新确认。"}
```

任务失败通过 `error_code` 与 `error_message` 表达。所有说明来自本地固定映射，验证错误不回显输入，供应商异常不回显密钥或 URL。

## 持久化与资源边界

- SQLite schema 从 1 升至 2，新增 `task_events`；任务变化与事件写入在同一事务提交，失败共同回滚。
- 首次打开旧库时保留已有需求、确认、用量、结果和幂等键，为旧任务建立当前快照；旧运行中的任务仍中断，不自动恢复收费调用。
- 未知版本拒绝启动。升级后旧 V0.6.0 不能读取该 schema；需要回退时使用停服期间备份的旧库。此轮测试均使用临时数据库，没有迁移用户实际数据库。
- 全服务最多 16 条 SSE 连接，超额返回 503、`event_stream_limit`；默认每 0.25 秒检查本地事件。多个页面不增加任务数或外部调用数。
- 不为每个客户端积压无限消息队列；发送阻塞超过 15 秒断开，释放连接槽位。慢客户端重连可能收到 reset。
- CLI 服务关闭最多等待 HTTP 连接 5 秒，随后清理连接和工作者，避免长连接阻止停服。
- 保持本机单用户、单进程模式，没有身份认证、跨用户隔离、前端界面或持久化 Agent 检查点。
