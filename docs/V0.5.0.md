# V0.5.0 需求确认与交通时长校验

## 范围

在 V0.4.0 工作流修复（`3612c13`）上增加需求确认、地图出发位置选择、驾车单程时长校验。
不增加地图服务、自动坐标补全、费用抓取、HTTP API、数据库或前端。

## 用户流程

1. 输入自然语言需求；最多一次 Qwen 调用提取草稿，未知字段为空。
2. CLI 展示全部字段。输入编号本地修改、清空；输入“确认”接受当前完整预览。城市和风格为必填。
3. 驾车且有具体地址时，按确认的城市和地址查询地图定位，用户选实际出发位置；即使只返回一个位置也不自动确认。可跳过。
4. 开始选景、按需路线与天气，再提交方案。超时的候选标为“不符合”，保留作比较，不伪装成满足约束。
5. 无坐标、无已选起点、无路线、未指定时长或不支持的交通方式均标为“信息不足”。总预算缺乏完整费用来源，明确标为信息不足。

草稿提取失败可手工填写，不自动重试；取消不会开始地图调研，但已经进行的提取调用可能产生费用。
相对日期不会自动换算；用户可在确认页直接填写 YYYY-MM-DD。日期/交通等修改后必须再次确认当前预览，重新规划不会复用旧证据。

## 可信边界与预算

- `confirm_brief` 是可信宿主入口，不是模型工具；`BriefDraft` 拒绝 `confirmed` 等额外字段。将来 HTTP API 必须由独立用户交互调用确认，不能把 LLM 的确认标志当用户接受。
- 确认数据保存为不可变 JSON 快照，读取时重建模型，列表修改不能污染原快照。`execution_scope` 核对原始请求并保存确认编号。
- 准备工具不能改写快照；确认模式下不再向模型提供准备工具。Supervisor 与地图/路线专家得到确认数据；出发定位由宿主完成，Route Agent 不再提供自行定位工具。
- 定位证据保留实际查询城市、地址、返回地址和坐标。选择回调只能返回本次结果 ID，不能替换坐标；用户选择地图点不等于地理或摄影现场核验。
- 地图治理层在付费/配额调用前检查驾车方式、起点和本次候选坐标。注册路线时写入确认编号与起点证据 ID。最终提交再次检查，不仅依靠提示词。
- 交通状态为 `meets` / `not_met` / `unknown`，只有绑定成功的路线才可比较。40 分钟与 2400 秒为符合，2401 秒即不符合；0 是有效上限，不等于未填写。比较依据是查询时估算，不保证未来路况。
- 模型未提交路线 ID 时，后端匹配本次已有绑定路线；采用匹配到的首条地图路线，不额外搜索最低时长。显式提交错误路线则校验失败，允许在原预算内纠正。
- 提取的尝试、已知 Token 和 usage 缺失计入同一请求的 12 次/40000 Token 阈值。出发定位及其重试计入 8 次地图总额度；搜索 2 次、天气 2 次、图步骤 40 保持不变。
- 提取超时最多 90 秒；确认后定位及规划仍使用 180 秒执行截止时间，用户等待选择出发点的时间不计入。需求原文与确认快照合计受 12000 字符输入限制。
- 失败时部分输出也会附加确认信息及已有有效路线的时长校验。安全 Trace 仍仅记录计数、状态和耗时，不保存需求、地址、坐标或密钥。

## 离线验证

使用现有虚拟环境运行 `python -m unittest discover -s tests -q`：115 项通过（原 86 项加 29 项）。
`ruff check src/scene_pilot tests`、`uv sync --locked --offline` 通过。本次没有调用真实 Qwen 或高德。

重点覆盖：

- 未确认/取消不开始地图规划；缺核心字段不能确认；修改和清空字段；禁止模型自报确认；快照不能被外部列表修改。
- 模型提取失败脱敏、无重试，长输入不调用模型，提取费用计入原预算。
- 多个定位结果必须选择、错误/跨结果 ID 不接受；错误城市/地址/起点/终点在上游调用前拒绝；步行与公交不使用驾车结果。
- 时长恰好相等、超出 1 秒、0 上限、缺少路线/确认/时长；显式假路线拒绝；省略路线 ID 不能隐藏已知违规；部分结果保留校验。
- 真实 Deep Agents 图 + 离线脚本模型：三个路线、天气、提取合计 12 次模型尝试，6 次地图尝试；Supervisor 最后模型步骤为 33，在原 40 步内完成。
- 缺坐标的确认流程仍完成提交，Supervisor 最后模型步骤为 27；不抬高任何执行限额。

## 限制

- 新确认流程尚未真实 Qwen/高德验收；实际工具调用遵循、定位响应格式及交互体验仍需后续少量受控验证。
- 当前仅有驾车路线能力；地名宽泛、地图坐标缺失时应修正地址或接受未知，不能猜坐标。
- 硬规则只覆盖单程交通时长。确认了预算或场地要求不等于已验证费用、许可、城市行政归属、审美或现场条件。
- `completed` 是提交完成状态，不是所有约束都符合。模型摄影建议仍为推断，不能覆盖后端校验结论。
- 保留旧 `arun(agent, request)` 调研调用，但未确认模式的交通校验始终 unknown；程序调用方需要按 README 的宿主确认契约接入。
- 确认与证据仅在内存中，无恢复会话/数据库。修改已确认需求应新建确认和新一轮规划。
