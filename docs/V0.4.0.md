# V0.4.0 天气与太阳时段验收

## 本次范围

为真实地图候选增加拍摄日期对应的区域天气预报、日出、日落及黄金时段。
继续保留 V0.3.1 的 Deep Agents 主/子 Agent、证据来源、调用预算、人工实拍检索词和安全停止。
不增加天气 Agent，不增加额外模型调用链；太阳计算完全在本地完成。

## 用户可见行为

1. 明确提供 `YYYY-MM-DD` 后，需求工具保存该日期到本次运行。相对日期不猜测，要求补充。
2. 主 Agent 选出最多三处真实 POI 后，一次调用条件工具；工具只接受本次 POI 证据编号。
3. 后端从地图证据取坐标/城市，计算太阳时段并查询天气。模型不能填写天气、太阳时间或另造坐标。
4. 最终方案展示区域、适用日期、天气来源、查询时间及服务返回的发布时间（若有），太阳时间标为天文估算。
5. 没有日期、坐标、区域或天气能力时分别保留未知，不妨碍已有地点和其他计算结果输出。

天气状态：

| 状态 | 含义 |
|---|---|
| available | 地区/日期匹配，服务发布时间距检查时不超过 24 小时，未来偏差不超过 10 分钟 |
| reference | 日期匹配，但服务未返回发布时间，或仅有搜索城市上下文而缺少 POI 区域字段；仅供参考 |
| unknown | 没有对应日期、地区不匹配、过期、没有能力、格式异常、超时或预算耗尽 |

`available` 也不表示现场已核验。逐日区域预报不能推出具体机位、小时级降雨、云量或阳光穿过树林的情况。
当前气象工具只返回实况时不将实况替代未来预报。过去日期不向当前天气接口发请求。

## 工程边界

- 天气最多尝试 2 次（含网络重试），计入现有高德总尝试上限 8。未提高模型预算。
- 相同城市查询沿用 300 秒请求内缓存。优先使用 POI 地图区域；都缺失时可按实际搜索的 `city` 参数查询参考天气。
  `query_city` 是搜索上下文，不是 POI 城市事实；该路径必须标为 `reference`、`area_basis=search_city`，并提示行政归属未核实。
- 有 adcode 时校验相同地区或同城市行政区；无 adcode 时校验实际查询区域及返回城市名，仅允许末尾“市”的名称规范化。
- 支持标准天气响应和现场观察到的官方 MCP 精简格式。后者没有 reporttime/adcode；严格保留缺失状态。
- 需求、证据、天气和条件报告都只存在本次内存上下文。Trace 仅记 `weather_attempts`、`solar_calculations` 等计数，不记录原始需求或天气原文。
- 原有 `select_amap_tools` / `load_amap_tools` 从两列表返回值变为三列表（地点、路线、天气）。内部调用已同步更新。
- 新依赖 Astral 3.2、tzdata；现有依赖版本未升级。`uv.lock` 的格式 revision 由本机 uv 生成，未人工修改。

- 覆盖重复查询缓存、三候选上限、跨请求隔离、缺日期不调用、天气能力缺失、共享调用额度、传输超时与取消时保留太阳结果。
- 覆盖杭州夏冬昼长、北京时间事件日期和先后顺序、极昼缺失事件、无效坐标。
- 真实 Deep Agents 图使用脚本模型完成“保存需求→委派地点查询→条件查询→最终提交”，确认模型自由文本不覆盖后端报告，原始 maps_weather 不暴露给模型。
- 2026-10-16 共做两次杭州天气调用（未做传输重试）：首次确认实际精简格式并发现与普通 Web API 文档不同；适配后第二次成功登记 1 条天气证据，包含 2026-10-16 至 2026-10-19 四个日期。
- 另做一次地点搜索和一次详情查询，确认两者可能都省略城市/行政区。因此新增搜索城市来源标记，并在离线真实图测试中覆盖与该实际响应一致的缺失字段情况。
- 未调用真实 Qwen，未宣称本轮完成付费模型端到端效果验收。测试中的所有模型与地图均为离线替身；上述服务检查是单独的人工集成验收。

## 当前限制与下一步

太阳计算固定使用国内选景默认北京时间和海拔 0 米，高德坐标直接作为近似输入，不做测绘级坐标转换；不考虑遮挡、天气和现场朝向。
黄金时段按太阳高度 -4° 至 +6° 定义，计算结果不是摄影质量保证。本轮未添加任意时刻太阳方位/高度角查询。
用户原文中的日期匹配只证明字面出现，不证明它一定是拍摄意图；模型提取的其他需求也尚未经过用户确认。
下一步应先建立需求确认流程，再进行预算、路线起点/方式、许可和时间等本地硬约束校验，随后推进 FastAPI/SSE/SQLite。

Scene 连续两次搜索成功，第三次周边搜索被额度限制；主 Agent 又提出第三次更新计划，随即 `GraphRecursionError`。
本次共 11 次模型尝试、2 次实际地图尝试、1 次额度拒绝、0 次天气查询。没有达到全局 12 次模型上限，先耗尽的是图步骤。

在锁定依赖上用脚本模型复现后，Supervisor 的模型节点位于第 4、11、18、25、32、39 步。
每轮含摘要检查、模型额度检查、模型、工具额度检查、模型计数更新、待办检查、工具执行等节点；
`trigger=None` 虽已关闭摘要模型调用，仍保留 `before_model` 空节点。第 39 步模型提出待办更新后，后续节点已没有空间。
Scene 的模型节点为 2、7、12、17；子图有自己的步骤计数，不能将其与父图步骤直接相加，但模型调用占共享额度。
仅缩短提示词、缩短工具文本或保留原先只走少数阶段的 78 项测试，不能证明完整流程能在 40 步内提交。

- `src/scene_pilot/agents/subagents.py`：Scene 接入上述工具检查，明确文字/周边搜索共用额度，缺坐标不应触发无限换地点搜索。

- 本文记录原因、验收及限制。合计新增 1、修改 5、删除 0 个文件；不含用户本地 `llm.py` 的未提交配置。

修复后离线测试总计 86 项通过。完整回归中 Supervisor 模型节点位于第 3、9、15、21、27、33 步，
校验成功后通过已有节点结束，没有再次付费生成总结；三候选缺坐标流程共 9 次模型调用，三路线+天气流程共 11 次，
均在原有 `recursion_limit=40`、全局模型上限 12 和地图上限 8 内完成。地图适配、证据校验、密钥处理和 Observer 失败降级代码均未修改。
本轮没有调用真实 Qwen 或高德；真实模型是否遵守工具筛选和批量调用安排仍待后续少量验收，不能保证任意重复或纠错序列均能在预算内完成。

坐标分析：适配器仅从 `poi.location` 接受服务返回的经纬度；有 POI ID 且 location 缺失、空字符串或空列表时，保留地点并将坐标置为 None。
非空但格式错误的坐标会导致该条目被拒绝，不会被悄悄变为正常坐标。现有安全 Trace 不含原始响应，尚不能确认本次服务到底省略字段还是使用了未支持的字段结构。
本轮不猜测新字段映射、不自动增加地图调用。后续合理补全顺序是：仅对已选 POI ID 查详情，核对返回 ID 相同且 location 完整有效；
以新证据编号引用完整记录，不篡改旧记录；详情仍缺失则保持未知。若要进一步地理编码，必须另行校验城市、完整地址和地点身份，不能直接把同名地址结果冒充该 POI 坐标。
